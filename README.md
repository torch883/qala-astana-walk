# QALA · ИИ-помощник по прогулкам в Астане

Рабочий Streamlit-прототип: настоящие POI из OpenStreetMap, локальные мультиязычные E5-эмбеддинги, FAISS, фильтры времени и доступности, ru/en/kk, карта и проверяемые рекомендации.

## Быстрый запуск

Нужен Python **3.11 или 3.12**, 64-bit. На этой машине проверяется Python 3.12. Windows поддерживается; `make` необязателен.

```powershell
cd path/to/astana-walk
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app.py
```

На macOS/Linux: `source .venv/bin/activate`. После установки: **`make run`** или **`streamlit run app.py`**. Адрес: http://127.0.0.1:8501. Приложение по умолчанию слушает только localhost.

На машине, где собран этот проект, также работает `powershell -ExecutionPolicy Bypass -File .\Start-Demo.ps1`: скрипт находит уже подготовленное окружение в рабочей папке. В переносимой копии сначала выполните обычную установку выше.

Снимок `data/pois.json`, `pois.parquet`, исходные ответы Overpass и FAISS-индекс включены в Git-репозиторий. Веса ONNX-модели находятся в полном архиве [релиза v0.1.0](https://github.com/torch883/qala-astana-walk/releases/tag/v0.1.0). Если вы клонировали репозиторий, после установки зависимостей один раз выполните `python -m data.download_model`, затем `streamlit run app.py`. Без весов приложение явно включает лексический fallback.

Полный архив релиза уже содержит модель. Первая загрузка модели в память может занять несколько секунд; она выполняется один раз. Для обычного ответа сеть не нужна. Карта использует браузерную библиотеку; подложка OSM включается отдельно.

## Семь кнопок для жюри

1. Прогулка у Mega — реальные варианты на 30–60 минут.
2. Кофе и розетка — unknown для неподтверждённых удобств.
3. С ребёнком — площадки/музеи, без обещания интерактивов.
4. Перед вылетом — честный отказ при недостаточном резерве.
5. Ночная Астана — проверка расписания на весь визит.
6. Пересадка 7 ч — «Астана за пересадку» с крайним временем выезда обратно в аэропорт.
7. Мороз −24 °C — только места в помещении и тёплый путь через ТРЦ.

Кнопки устанавливают публичные демо-локации и фиксированное время. Свой запрос вводится в чате; время и точку можно менять. Карточки — альтернативы, если отдельный маршрут не сформирован.

## Погода и тёплые маршруты

Прогноз [Open-Meteo](https://open-meteo.com/) запрашивается на выбранный час только для центра Астаны: точка пользователя в погодный сервис не уходит. Три уровня: норма, «осторожно» (места на улице ниже в списке, в карточке — совет) и «суровая погода» (ощущается ниже −20 °C, ветер от 12 м/с, гроза или сильные осадки). В суровую погоду места на улице не предлагаются, а пеший путь допускает отрезки по улице не длиннее 8 минут — при необходимости через открытый ТРЦ или вокзал (`data/warm_hubs.geojson`, 27 контуров из OSM). Ночью ТРЦ с неподтверждёнными часами не используется. Пороги — в `config.yaml`, раздел `weather`. Если прогноз недоступен, погода не учитывается, и это видно в интерфейсе. Сценарии «мороз», «метель», «дождь», «жара» в боковой панели помечены как сценарий, а не прогноз.

## «Астана за пересадку»

Запрос вроде «пересадка 8 часов» или «транзит, вылет в 22:30» планируется назад от вылета: 45 минут на выход из аэропорта, такси до точки высадки и обратно (по прямой × 1,3, скорость трассы, запас на пробки ×1,25, 10 минут на подачу), резерв 120 минут до вылета. Пробуются точки высадки Байтерек, Хан Шатыр, Экспо и Mega Silk Way; выбирается та, где помещается больше мест и мини-маршрут. В ответе — крайнее время выезда из города; `core.layover.check_plan` проверяет, что прогулка укладывается в окно и резерв не тронут. Если на город остаётся меньше 45 минут, QALA советует остаться в аэропорту. Визовые правила и оформление багажа не проверяются — об этом есть предупреждение. Числа — в `config.yaml`, раздел `layover`.

## LLM и режимы

```powershell
Copy-Item .env.example .env
```

В `.env` задайте `LLM_PROVIDER=gemini` и `GEMINI_API_KEY`. Модель задаётся `GEMINI_MODEL`; выберите доступную вашему проекту модель с JSON Schema. Используется REST generateContent с responseJsonSchema. Ключей в репозитории нет. Без ключа включены локальные правила и шаблоны; это явно видно в UI. Живой API без ключа не проверен.

- `EMBEDDING_BACKEND=e5` — основной режим; при недоступности индекса явно включается TF-IDF.
- `DEMO_CACHE=1` — только точные пять заранее записанных сценариев; часы и ограничения перепроверяются. Произвольные запросы не сохраняются.
- `WEATHER=auto` — погода по умолчанию: `auto` (прогноз Open-Meteo), `off`, или сценарий `frost`/`blizzard`/`rain`/`heat`/`mild`. Тесты и eval работают без сети.
- `LLM_TIMEOUT_SEC=3` — тайм-аут ожидания API. Сеть, разбор и повтор могут увеличить общее время ответа; целевой быстрый режим проверяется отдельно в eval.

## Обновить данные

```bash
python -m data.collect --refresh
python -m data.collect_warm --refresh
python -m data.enrich
python -m core.retrieve --build
python -m eval.build_cache
python -m eval.run_eval
```

Без `--refresh` сборщик воспроизводит очистку из сохранённых ответов Overpass. При недоступности API он завершится ошибкой и не подменит данные выдуманными POI. `gold_review.yaml` применяется автоматически; свежий снимок может потребовать повторной редакторской проверки. Обогащение хранится отдельно с `generated=true`: при ключе используется Gemini, без него — явно помеченный шаблон категории. `--templates` принудительно отключает API; `--limit 50` ограничивает объём платного обогащения.

Если модели нет, `python -m core.retrieve --build` попытается скачать E5 через Hugging Face. Для переносимой полной копии сохраняйте `data/models/e5-small/`. `MODEL_CACHE_DIR` позволяет указать другой абсолютный путь.

## Проверить

```bash
python -m pytest -q
python -m eval.run_eval
python -m eval.build_cache
```

`eval/report.md` содержит реальные результаты последнего прогона; `eval/answers.json` — ответы на публичные сценарии. Фикстуры с изменёнными часами и инъекцией существуют только в памяти теста. Онлайн-LLM не покрыт без ключа; поддельный провайдер в unit-тесте проверяет повтор и fallback.

## Что находится в проекте

- `data/` — сбор, отдельное обогащение, исходные OSM-ответы, очищенный снимок, отчёт качества, 50 редакторских проверок по тегам.
- `core/` — разбор, geo, часы, поиск, ранжирование, генерация, схемы, валидация, маршрут и приватный режим кэша.
- `tests/scenarios.yaml`, `eval/` — 25 сценариев и воспроизводимый отчёт.
- `docs/` — концепция, RAG, сценарии, этика, текст 7 слайдов, сценарий видео.

## Ограничения

OSM может быть неполным и устаревшим. «Проверено по источнику» означает редакторское чтение тегов ассистентом, а не звонок заведению или проверку человеком на месте. Часы есть у 39,9% записей (безымянные площадки и парки почти всегда без расписания), розетки почти не описаны. Пешеходный путь — оценка по прямой, не навигация; центры больших объектов не равны входам. Наличие wheelchair=yes у места не подтверждает весь путь. Расписание кино/театра, события и пробки не подключены. Погода — почасовой прогноз для центра города, без гололёда и микроклимата. Тёплый путь — оценка по прямой до контура ТРЦ; входы и проход сквозь здание не проверены, часы есть лишь у 5 из 27 узлов. Время такси на пересадке — оценка с запасом, не расписание; визы, багаж и задержки рейса не проверяются. Мини-маршрут строится только если все остановки и возвращение помещаются в бюджет. Казахские шаблоны нуждаются в проверке носителем. Фильтр вредных запросов основан на правилах и не является полной защитой.

Не выполнены без внешнего доступа: проверка живого Gemini, независимая проверка мест человеком, запись и публикация YouTube-видео. Вместо публикации включён сценарий записи. Метрики eval не являются пользовательским исследованием.
